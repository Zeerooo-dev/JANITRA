# JANITRA company setup follow-up review

Mode: after, selected by the user. Scope: the first-Supervisor company form and authentication integration. This extends audit-001; it does not approve unfinished operational screens or certify production security.

Direction: use the existing JANITRA navy, Roboto, light surfaces, 24px form padding, and native Material controls. The user requested manpower-company input during setup. ENERGY 1 / RHYTHM 1 / MOTION 1; Register Company is the focal action. No illustration, dashboard navigation, or extra organization fields were invented.

Hard gate: no em dashes, invented statistics/testimonials, placeholder navigation, decorative assets, or unsupported security claims in the form. Widget tests confirm scrolling at 320px with 200% text. The 393x852 browser preview shows contained headings, labels, and actions. Existing measured navy/text contrast remains unchanged.

Function checks: browser walkthrough enabled Flutter semantics, submitted empty values, entered clearly labeled local test names, submitted with Enter, saw the injected server rejection, retried successfully, and signed out to login. Widget checks cover validation without writes, duplicate-click prevention, rejected requests without success, trimmed request parameters, and successful completion. Loading disables both actions; errors remain visible and allow retry. The server tests separately enforce real authorization.

The browser used an isolated mocked API to exercise the actual application widgets and AuthGate, not a live Supervisor account. The temporary preview entry point was removed and is excluded from the installed app sources. Screenshot: `docs/screenshots/company-setup-preview.jpg`.

Purpose and quality gates: existing theme and control patterns are reused; copy describes agency setup and postpones optional client/site entry. Every form action has a real handler. No extra packages were added. Android compilation, analyzer, widget checks, design checker, and isolated PostgreSQL checks passed for this scope.

Not checked: real Android keyboard/secure-storage behavior, valid-user login, email invitation/recovery round trip, live Data API permissions, and PIN operations. These remain explicit release blockers.

Deployment follow-up: the invited-user password step reuses the reviewed native password form with the title `Set Your Password`. It keeps validation, loading, retry, and confirmation controls; both fields are cleared after attempts. A widget regression verifies rejected updates stay on the form and accepted updates lead to company setup without signing the new user out. Twelve widget tests and the rebuilt APK pass. Live anonymous Data API denial is now verified; physical-device invitation/recovery and PIN operations remain unverified.
