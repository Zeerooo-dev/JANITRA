# JANITRA Build 12: scheduling deletion

October 18, 2026, Asia/Manila. Flutter version `1.0.0+12`.

## What changed

- Supervisors now have a Delete control beside each activity, work shift and cleaning schedule in Schedules & Activities. Existing tap-to-edit behavior remains available.
- Deletion opens a confirmation explaining its consequences. Cancel or dismiss leaves the list unchanged and makes no refresh request. A failed request keeps the item visible and supports a retry with the same request identifier.
- Deleting an activity or shift also removes its linked cleaning schedules. Deleting one cleaning schedule keeps its activity and shift.
- Only future tasks still scheduled and unsubmitted are cancelled. Tasks already due, submitted work, review decisions and audit history remain available. Deleted definitions are retained as inactive database tombstones for historical references, hidden from ordinary scheduling queries by RLS.
- Server checks enforce the current authenticated session, active Supervisor role and exact workplace scope. Personnel cannot delete scheduling items. Concurrent task generation cannot recreate deleted work; stale edits cannot restore deleted definitions. Retries are bound to the action and payload and record one deletion audit event.
